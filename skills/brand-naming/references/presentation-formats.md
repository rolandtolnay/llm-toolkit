# Presentation Formats — Longlist Review, Proof of Concept, Final Dossier

## Longlist review (user checkpoint after convergence)

Present 12-20 names, grouped by territory, each with a one-line gloss — never the raw
several-hundred-name trash lists, and never a bare spreadsheet-style dump.

Before showing the names, deliver the comfort-trap briefing (adapt, don't recite):

> Before you react: the names most likely to work will probably NOT be the ones that feel
> comfortable. Comfortable + familiar = invisible — safe consensus choices disappear into the
> category. The right name usually sits in the tension zone: it's polarizing, some part of you
> resists it, and that resistance is energy. When Intel's engineers hated "Pentium," Andy Grove
> read the polarization as proof the name had energy inside. So react honestly — but tell me
> *which names create a reaction*, even a negative one. "Nothing" is the only bad answer.

Reaction protocol — for each name ask the user to tag: **love / intrigued / nothing / hate**,
plus free-form notes. Then:

- **love + intrigued** → advance to screening.
- **hate with energy** (visceral reaction, strong argument against) → probe once: what exactly
  triggers it? If the objection is practical ("that'll never pass legal", "too expensive to own")
  reframe it as a problem to solve — "how would we modify it so it works?" — before letting it die.
- **hate** that survives the probe → **parking lot**, not deletion. The BlackBerry rule: park
  rejected names visibly ("off the table for now — I may bring it back"), and DO bring one back
  at the final stage with evidence if screening and scoring say it's the strongest candidate.
- **nothing** across the board → the longlist failed; trigger the redial cycle (see SKILL.md
  edge cases), don't push forward with names nobody feels.

## Proof of concept (top 5-7 names, after screening)

Names are never judged from a list — they're judged in the world. For each finalist, render
these five contexts as plain text/markdown:

1. **Press headline** — a TechCrunch/WSJ-style launch headline:
   `"<Name> raises $12M to make <category> feel <ultimate benefit>"`
2. **Tagline lockup** — name + supporting line that makes the concept land instantly, the
   "consumers aren't stupid" test: `Feather — the lightweight fiber you need.` The name can be
   bold when one line of copy closes the gap (Swiffer never needed "mop" in its name).
3. **Sponsor line** — Lexicon's favorite believability probe, a prestige-ad frame:
   `"Companies that run well run on <Name>."` (adapt the verb to the category).
4. **App store / shelf card** — name + subtitle + one-sentence description as it would appear
   at point of discovery, next to two real competitor names for contrast.
5. **Spoken introduction** — how the founder says it out loud:
   `"We're <Name>. We <what it does in eight words>."` Read for mouth-feel and cocktail-party
   repeatability.

**The believability test**: for each mockup, apply the sub-second judgment — "Is that
believable?" Not "do I like it": does the gut lean toward *"I think I believe this"* — the way
"Microsoft could have a cloud called Azure" is instantly believable. Record pass/lean/fail per
context. A name failing believability in 3+ contexts drops out regardless of its scores.

Optionally (offer, don't assume): render the boards as a single HTML artifact — one section per
name showing the five contexts styled like real surfaces (headline typography, app-store card).
Load the artifact-design skill first if the user says yes.

## Final recommendation dossier (00-recommendation.md and final message)

Structure:

```markdown
# Naming recommendation: <subject>

## The strategy in one line
<name_must_say + ultimate benefit, one sentence>

## Recommended: <Name>  (and optional second recommendation)
- **The story**: where it came from, what it evokes, why it's surprisingly familiar
- **Why it wins**: tied explicitly to the four questions and the creative framework —
  original in category / processing fluent / unexpected here
- **Sound**: 2-3 lines from the scoring table (the specific letters/structure working for it)
- **Screening**: verdict + the caveat line
- **Best supporting line**: the strongest tagline from proof of concept
- **The risk**: name the polarization honestly — who will hate it and why that's energy,
  not error

## Also strong: <Names 2-5>
Per name: 3-5 lines — story, strongest asset, screening status, and the one reason it ranked
below the recommendation.

## Parked with potential
<Names from the parking lot worth revisiting if the finalists die in legal — with the
evidence-based case for each, BlackBerry-style.>

## What happens next
1. Trademark attorney review of the top 2-3 before any commitment (screening here was
   knockout-only).
2. Domain/handle acquisition for the chosen name.
3. Launch with a story: names matter most in the first 90-120 days — the name gets attention
   and holds it while the market dynamics take over. Commit with enthusiasm; a right name
   launched apologetically performs like a wrong name.
```

The recommendation must take a position: 1-2 names, ranked, with justification. Presenting five
equally-weighted options is the invisible-zone consensus move this whole playbook exists to
prevent. Recommend the name with the most energy that survives believability — not the one the
user is most comfortable with — and say so explicitly when they differ.
